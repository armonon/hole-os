# Atlas and Tongue supported paths

Source/API review: 2026-10-26. `src/world-tools.js` uses shared Core records and the continuity context. It exports `HoleWorldTools.render('atlas'|'tongue',ctx)` and `dispose()`. Call dispose when leaving a view to abort a pending translation/model operation and stop local speech.

Atlas saves named coordinates, explicit time zones, visit dates, notes, project membership and one related file reference as `links` records with `kind:'atlas-place'`. It validates coordinate/date/zone ranges, saves/reopens through Core, sorts an itinerary, exports real JSON and can create a Day event using the existing daylight-saving-aware event validator. Original OpenStreetMap links are retained and contain only coordinates. No location request or automatic upload occurs. [OpenStreetMap copyright and license](https://www.openstreetmap.org/copyright).

`src/atlas-map.js` adds a bundled offline world map using the original 127 Natural Earth 1:110m land polygons, drawn in an equirectangular longitude/latitude projection. [Natural Earth primary terms](https://www.naturalearthdata.com/about/terms-of-use/) place its map data in the public domain; [land data description](https://www.naturalearthdata.com/downloads/110m-physical-vectors/110m-land/) identifies the coarse land/island layer. The exact upstream commit, source URL and SHA-256 are recorded in `src/vendor/atlas/README.md`. All data is served from the Hole build. No tile server, map account, geocoding, GPS or political boundary claims are added.

Map controls support bounded 1–8× zoom, pointer pan, arrow-key pan, +/− zoom, Home reset, keyboard-operable markers and a separate place-button list. Map coordinates project directly from the saved place; they are not inferred from its name. View position saves per project and survives reopening. The map displays at most 200 markers; the full itinerary remains in the list. Coarse coastlines omit small features and are not road maps or navigation guidance. Missing bundled data leaves the saved-place list available with an actual error.

The existing full private itinerary export remains. A separate reviewed trip export uses the existing `hole.atlas/1` JSON schema and excludes notes and source-reference IDs by default; users explicitly include either. Coordinates, names, dates and time zones are always exported. Nothing is sent or published. Import validates the entire file before writes: at most 200 places and 2 MiB UTF-8 JSON, strict coordinate/date/zone/name/note bounds. Imported records receive fresh deterministic local IDs in the selected project. Foreign file/project/place IDs remain inert `importedReferences`; they never open or resolve another device's files automatically. An imported place may later receive an explicitly chosen local linked file.

Core exposes no general multi-record batch transaction. Import therefore writes a durable fingerprint/progress record before place creation, retains already saved places after a failure, reports the exact completed count and resumes the same normalized file/project without duplicates. A completed import is recognized on retry; existing place edits are never overwritten. This is resumable partial import, not a claim of atomic multi-place commit. Local JSON exchange supports sharing trip copies; connected collaborative editing, routes and Circle publishing still require qualified providers.

`node --test tests/atlas-map.test.mjs tests/world-tools.test.mjs` passes 7 checks including real geometry, bounds, export privacy and an injected storage failure followed by resumable import. `tests/verify-atlas-browser.mjs` runs the actual source UI or, with `HOLE_ATLAS_SHELL_URL=http://127.0.0.1:5193`, the integrated build. Chrome 155 evidence uses two separate disposable persistent profiles: invalid coordinates refused; actual place/marker; keyboard pan/zoom and saving while offline; close/reopen; actual downloaded JSON inspection; explicit private-note export; second-profile import with fresh identities/unresolved references; duplicate retry and invalid-file refusal. No external request was observed during map operations. Use `?offline-test=1` for the additional service-worker offline reload assertion.

Tongue feature-detects `window.Translator.availability/create`, validates language tags, checks the exact language pair, and distinguishes available/downloadable/downloading/unavailable. Model creation/download happens only after the separate labelled user action; it reports download progress and uses cancellation/cleanup. It preserves the original input if the text/language changes during asynchronous processing. There is no invented translation or server fallback. Source: [Chrome Translator API documentation](https://developer.chrome.com/docs/ai/translator-api).

Phrase cards are either actual browser translations with recorded provenance or explicitly user-authored content. Exact written-answer practice records attempts, correct answers and an inspectable next-review interval; accent differences remain significant. This is not a pronunciation or fluency score. Speech uses only device voices whose `localService` flag is true; an unavailable voice is reported honestly. Source: [SpeechSynthesisVoice.localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService).

Cards save/reopen as Core `memory` records, export JSON, and optionally supply user-entered subtitle times. SRT export produces real timestamps/text and refuses invalid or overlapping cues. No audio transcription, automatic subtitle alignment, imported-media speech recognition, provider conversation engine or automatic pronunciation assessment is claimed. Those require an actual qualified engine or authorized provider and their own data-flow tests.

`node --test tests/world-tools.test.mjs` covers coordinates, invalid dates/zones, private details excluded from map URLs, subtitle output/error cases, actual written-answer progress and download-free capability checks. Browser model execution is unverified until a supported runtime/language pack is available; feature-detection fixtures test behavior, not translation quality. Core persistence/backup coverage applies to the new record types. Physical-device speech and model download behavior require separate browser evidence.
