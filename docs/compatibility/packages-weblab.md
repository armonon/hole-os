# Bounded package kinds and WebLab developer tools

`package-model.js` and `package-studio.js` load after the existing extension model/UI. The UI wraps existing render/open/leave hooks, preserving `hole.tool/1`, `hole.weblab/1`, `hole.package/1`, and legacy tool package state keys. It reuses the existing tested bounded component runtime rather than running package source code.

Packages may be tools, bounded composed apps/instruments, appearance themes, registered-action workflows, or named Space templates. All have empty permission lists. Runtime version is 1; unknown kinds, incompatible runtime, unknown actions/parameters, duplicate component IDs, and out-of-bounds data are refused. Updates require a newer version of the same package kind, retain up to ten prior manifests, and use Core optimistic revisions. Rollback is also revision checked. Installing stores a manifest; it never applies a theme, executes a workflow, creates a Space, or grants access by itself.

Compositions use native `hole.utility/1` JSON with one to twelve stable component IDs, each containing a validated counter/checklist/timer/calculator config. Each component state is independently durable. Closing drains pending changes and timer state. Composed-package state is version scoped so rollback returns to that version's retained state; legacy tool packages retain their original `package-state:<id>` storage key. Create offers add/remove composition authoring, saving to a real Core asset, reopen, and export.

Theme application uses the validated welcome preference hook and saves a durable undo copy first. Workflows are validated against actual action schemas, then explicitly copied into recipes and opened in Flow review for input selection; installation never binds file grants. Space-template application calls the shell's bounded create-new-space hook, then stamps package provenance on its new scene. This two-step operation can leave a saved new Space if a later scene/provenance write fails; the UI reports the error and the already-created Space must be inspected before retry. Existing spaces are never overwritten.

WebLab adds console, error, rejection, and CSP violation output from the actual preview frame. Messages must match the frame window, opaque origin and current per-preview nonce. Diagnostic content is untrusted text and cannot grant host operations. Logs are capped at 100 lines of 2,000 characters. Existing source limits remain three files of 500,000 characters each. Stop removes `srcdoc`, navigates to a blank document, and invalidates the diagnostic nonce. The cooperative 30-second timer is not a hard CPU or memory boundary: a non-yielding browser script can obstruct it. No arbitrary executable package installation is enabled by these additions; hostile-code process isolation remains an unfinished qualification gate.

Verification: `tests/packages.test.mjs` covers durable install/update/reopen/rollback, stale rollback, kind/version/runtime/grant rejection and actual workflow/space bounds. Existing `extensions-ui.test.mjs` continues to pass. `tests/verify-packages-browser.mjs` passes installed headless Chrome 155 against actual Core and extension modules: composition author/use/state reopen, package review/install/use/update/rollback, and actual opaque-frame console/errors with denied IndexedDB/parent DOM/network and explicit stop. It does not fake shell appearance or Space hooks; those require integrated-build checks. Safari, physical devices, uncooperative CPU/memory stress and production release remain separate gates.
