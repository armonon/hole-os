# Declarative object packages

Momentous accepts additive `hole.package/1` kind `object`, runtime 1, empty permissions and exact authored provenance. Existing tool, instrument, app, theme, workflow and Space-template formats remain compatible. Installation/update/rollback uses the existing package store, monotonic update version check and ten retained manifests. Installing never places or changes an object.

`object` is `hole.object-definition/1`: plain label (1–80 characters), `circle|tile|pill` shape, six-digit hex `color` and `textColor`, optional boolean `counter` (default false), bounded initial count (±1,000,000) and step (±1,000). Unknown definition fields, SVG, raw HTML configuration, resource URLs, executable content and grants are unsupported. Labels use textContent. No remote fetch, dynamic code or package-provided CSS is used. The built-in Focus pebble demonstrates appearance plus optional state.

Use opens explicit project and x/y selection (±6,000). The destination must already exist. Placement creates a native `application/vnd.hole.object+json` asset with schema `hole.object/1`, exact source package ID/version/provenance/definition, independent counter state, and up to ten previous appearance definitions. It creates a latest-policy asset placement in the chosen project, preserving the normal stable asset identity used by Desktop, Canvas and Universe. Opening that asset renders the actual colored shape, editable label/colors/shape and optional counter. Existing project cards keep their ordinary file representation; this does not introduce a custom 3D mesh or ambient desktop widget.

Appearance edits and counter actions commit immutable asset versions with stale-base conflict checks. Save failures leave input controls available and the previous version intact. Counter controls persist on each acknowledged action; appearance fields require Save object appearance. Historical versions and pinned placements are read-only. Export downloads the exact selected native object bytes.

Package updates never change placed objects automatically. Use installed appearance explicitly adopts that package version while retaining the object's authored count. Local appearance customization is labeled separately from exact source provenance. Undo object appearance restores the prior definition/source metadata while preserving count; this creates a new native version rather than deleting history. Rolling back a package changes the installed manifest; applying its appearance to an object is another explicit action.

Core lacks a combined asset-and-placement transaction. Destination/geometry are validated before import. If import succeeds but position writing fails, the error reports the retained asset ID and the UI prevents blindly repeating the operation. The object is still a member of its project through projectId and can be opened from that project. No atomic multi-record success is claimed.

## Interfaces and evidence

`HolePackageModel` adds `OBJECT_MIME`, `objectDefinition`, `objectDocument`, `placeObject(core,manifest,{projectId,x,y})` and `editObject(core,record,operation,value)`, where operation is count/customize/appearance/undo. The existing `HoleExtensions.openAsset` wrapper mounts the renderer; no new script or shared-shell hook is required.

`node --test tests/packages.test.mjs tests/package-objects.test.mjs` passes six tests, covering existing kinds, bounded object validation, stable placement/native versions, stale edits, retained source/state, explicit update/undo/package rollback and partial placement failure. The existing `tests/verify-packages-browser.mjs` also passes compositions and package regressions plus actual WebLab diagnostics isolation checks.

`scripts/verify-package-objects-browser.mjs` passed Chrome 156.0.8078.48 against the actual integrated shell using the generated scripts without overrides, after an earlier source-override development pass. It uses a disposable persistent browser profile, closes/reopens it, and verifies actual UI install/place/edit, downloaded export bytes, package update, appearance undo, package rollback, retained counter/placement identity, six immutable versions and historical read-only controls. The test also rejects out-of-range placement before asset creation and then corrects/retries successfully. No physical-device, assistive-technology or external marketplace qualification is implied.
