# Public forms — local service qualification

The local Relay service supports explicitly published, expiring form schemas from selected immutable `application/vnd.hole.form+json` versions. The owner reviews the schema in Relay before publishing. The public representation contains only form ID/name, expiry, schema version and validated field IDs/labels/types/required flags. Saved local responses, source asset/version/project identifiers and unknown metadata are excluded. Later source changes do not alter the publication.

`POST /projects/:id/forms` requires current owner access and expected project revision. Owners list publications, retrieve responses at `GET /projects/:id/forms/:formId/responses`, export actual response JSON and revoke via DELETE. Current ownership determines response access after transfers. Public GET `/forms/:id` and POST `/forms/:id/submissions` require no account, while retaining exact configured browser Origin policy and the existing write-header requirement. Relay provides a public form ID entry before sign-in. This is an ID used in connected Relay, not a standalone hosted form website or an automatically delivered invitation.

The service persists submissions with copy-on-write durable transactions before returning a receipt. Same ID and answers retry idempotently, including after restart; different answers with the same ID conflict. Unknown answer keys, unsafe field IDs, invalid emails/numbers/calendar dates and wrong checkbox types are refused. Limits: 30 fields, 10,000 characters per text answer, 64 KiB submission body, 1 MiB source form, 1,000 responses per form, 100 publications per project, 1 minute–30 day expiry (default seven days), five new submissions per form/socket address per minute. Rate history survives restart, and raw addresses are not stored. Revocation/expiry checks run again inside the write transaction; they block new reads/submissions while retaining owner export. Existing downloaded copies cannot be recalled.

The browser retains answers and the retry ID while the form dialog remains open after a failed request. Closing or reloading discards an unsubmitted form; no durable guest draft is claimed. A success message appears only after an actual service receipt.

Evidence: `tests/public-forms.test.mjs` validates schema filtering, owner permissions, answer bounds and durable-state retry/rate rules. `tests/service.test.mjs` includes actual HTTP guest submission, service restart/idempotency, private owner export, large-body refusal and revoke. `node tests/verify-public-forms-browser.mjs` passed Chrome 155 with separate disposable owner and guest contexts: actual review/publish clicks, guest submit, owner read, downloaded JSON byte inspection and guest denied after revoke. The browser harness runs the actual source modules and HTTP service; it is not physical-device evidence.

Production remains gated on hosted service/identity/backup and abuse qualification. Socket-address limiting is local protection, not a distributed anti-abuse system. A reverse proxy needs a separately trusted address policy; arbitrary forwarding headers are deliberately ignored. No CAPTCHA, moderation, email delivery, production endpoint, cross-origin wildcard or public deployment is added here.
