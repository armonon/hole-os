# Actions and Flow integration

Load `core.js`, `actions-codecs.js`, then `actions.js`. There is no durable in-memory fallback. After Core readiness, `HoleActions.recover()` can mark abandoned action jobs and Flow runs interrupted when cross-tab Web Locks establish that no executor owns them.

`HoleActions.list()` / `get(id)` expose versioned typed metadata, JSON parameter schemas, readable parameter help, accepted MIME types, output policies, browser availability, capability requirements and cancellation/retry policy. Only implemented actions are registered. Native cutout, stem separation, BPM/key and speech models are not invented.

`preview(id,{inputs:[{assetId,versionId?}],parameters,projectId?})` resolves an omitted version to the current head and returns pinned input IDs, real image dimensions, planned crop rectangles/output sizes and upscaling warnings. The UI must show the plan and pass those pinned versions to the eventual run. PNG is lossless; WebP exposes quality. Browser encoders are checked by the returned MIME type, rejecting an unsupported fallback rather than renaming bytes.

`run(id,request)` returns a Promise with an immediate `.jobId` and resolves `{jobId,job,outputs:[{asset,version}],assets,versions,replayed}` after Core's atomic commit. An optional `onJob(job)` receives the authoritative ID when retrying an existing idempotency key. `cancel(jobId)` and `retry(jobId)` operate on durable records. `hole:action-progress` events expose jobId/status/progress/message. Durable progress is 0–100, and successful status is `completed`, matching legacy Activity.

Text save and image crop/resize/convert advance the same asset's immutable head using stale-base checks. Text branch, audio outputs and Release Pack create derived assets with source-version lineage. Original bytes remain readable. Cancellation is effective before the atomic output commit; completed outputs are never silently deleted. Reusing an idempotency key with different inputs/parameters is rejected.

Release Pack requires a normalized explicit focal point `{x:0..1,y:0..1}`. It creates 3000×3000, 1080×1920 and 1200×630 images and a valid UTF-8 ZIP containing the images and `manifest.json`. Aspect ratio is preserved by cropping, and any upscaling requires `allowUpscale:true`. Systematic filenames contain the project/source, role and immutable input version. ZIP STORE packages bytes without claiming compression. Source IDs, crops, dimensions, MIME types, sizes and settings appear in the manifest. The completed job and project memberships form the release collection.

Flow APIs are `saveRecipe(recipe,{expectedRevision?})`, `listRecipes()`, `previewFlow(recipeOrId,request)`, `runFlow(recipeOrId,request)`, `cancelFlow(runId)` and `retryFlow(runId)`. Recipe steps contain unique `id`, registered `actionId`, `parameters`, optional `from:'inputs'|earlierStepId`, and `outputIndex`. A run durably captures its recipe version/snapshot, concrete original inputs, per-step states/jobs and exact output references. Retry reuses successful outputs and repeats only unfinished steps. UI should explain downstream inputs that do not exist until an earlier step produces them; each engine still validates those actual inputs before execution.

Node tests exercise geometry, ZIP CRC/directory structure, PCM WAV encoding, requests/idempotency, cancellation, Core's actual IndexedDB version/job atomicity, stale-head rejection, project memberships, persistence across database reopen, partial Flow failure/retry and upscale consent. Image rendering in these tests uses a controlled Canvas stub; actual PNG/WebP pixel output and browser media codec behavior need browser QA.
