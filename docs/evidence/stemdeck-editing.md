# Bounded native arrangement editing

The retained browser source is `sattari-seo-20261026/source`, revision `ae9d4bfb82899e3b9d516a06d66b4915fc91b157`. This increment exposes its existing `trimClipStart` and `resizeClip` functions from `arrangementModel.js`; no additional runtime dependency or license footprint is added. Their original trim-source records preserve the source envelope and fades while materializing the selected window for older native readers.

`updateTrack(id, {muted,solo,gain,pan})` accepts only those fields: strict booleans, gain 0–300%, and pan −1 to 1. `updateAudioClip(id,{start,trimStart,duration,rate})` accepts only audio clips and the explicit field allowlist. Start moves the clip on the timeline; trimStart crops its source window before the requested move; duration invokes retained resize; rate changes source playback speed. Native ranges remain start/offset up to 86400 seconds, duration at least 0.001 seconds, and rate 0.25–4. These editable native ranges are distinct from the dry preview's 60-second bound. The UI describes the distinction.

Before an audio edit, the adapter reads the granted native archive and verifies an actual embedded mono/stereo PCM WAV header, exact RIFF length, one format/data chunk, sample alignment and rate. Actual source duration comes from source PCM frame count, not an untrusted manifest duration. Overruns and silently clamped trim/resize requests are rejected. No source audio bytes are changed. Unknown document fields, routing, automation and original trim source survive. The mutation lock blocks edits/save during asynchronous source admission, and the existing pending-save/export guard blocks new edits after ambiguous acknowledgement. Successful edits stop timeline playback, enter native Undo history, and become native recovery before Save to Hole commits an immutable child version. Session Undo is bounded to the existing twenty in-memory entries; saved Core versions remain immutable.

Raw inspector fields are separate from native document edits. Debounced, serialized bridge checkpoints retain up to 32 KiB of bounded per-record fields, including invalid strings, only under the exact asset/version binding. Apply validates and removes the corresponding raw patch only after successful native mutation. Close sends a parent/child flush handshake; the child rejects active native work and reports failed storage instead of claiming durability. The window remains open on failure and a retry can persist the same field text. No raw patch is silently applied to the native document.

The actual dry-preview limitations from `stemdeck-transport.md` remain: no rendered effects, routing, automation, fades, master processing or deck playback; original data is preserved for the full studio. Track controls affect the preview's native gain/pan/mute/solo scheduling, not a claim of full mix parity.

Untouched fields are compared with native values so initial flush does not create a false draft. The expanded transport actual-shell regression also passed, retaining sample-error-zero output, cancellation and bounds. Four new editing tests plus ten existing transport/adapter tests pass.

The child registers the flush listener before asynchronous initialization and gates its response on editor readiness. This closes the opening race where the runtime initial checkpoint could otherwise send its request before the listener existed. Failed initialization replies with an error; pending native operations refuse close.

Browser unload guard: child messages use exact bootstrap host origin and nonce; the parent checks the exact frame and nonce. Raw input increments an epoch before debounce. Each checkpoint acknowledges only the epoch it captured, so an old completion cannot clear a newer pending edit. Native busy state, ambiguous ACK and storage failures also keep the guard active; already-durable dirty work alone does not. The final built browser test dispatched a cancelable beforeunload event during the injected storage failure and observed prevention, then observed no prevention after successful durable retry. This tests the guard, not operating-system crash recovery or physical browser close behavior. Final editing and transport shell checks passed again after this change.
