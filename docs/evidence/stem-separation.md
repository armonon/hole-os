# Bounded local stem separation

`audio.stems` uses actual installed MIT demucs-web1.0.2 and ONNX Runtime1.30.0 CPU WASM. It produces drums/bass/other/vocals stereo44.1kHz16-bit WAVs atomically, each referencing the original immutable version and pinned model identity. Audio input<=16MiB, decoded mono/stereo<=15s; decoder resamples explicitly to44.1kHz. Browser decoding may allocate before post-decode bounds. No original bytes are rewritten. Separation can leak/omit/alter sources; no quality, musical-source isolation, native parity or music corpus accuracy claim.

One inference at a time, absolute180s deadline (parameter1–180000ms), cancellation terminates worker. All source lengths are padded to at least343980samples because the dependency otherwise computes zero segments for very short audio; output truncates to the exact original decoded sample count. Completed ORT feed/result tensors and session released. Model activations can consume hundreds of MiB; this is a runtime/selected-input bound, not a strict browser memory quota. Four maximum-length output WAVs total10,584,176bytes. CPU-only qualification; no GPU fallback claim.

`HoleModelStore.install(manifest,blob)`, `status`, `remove`, `read` use CacheAPI `hole-models-v1`, key `/__hole_models/<sha256>`, separate from Core/backup. Manifest includes id,bytes,sha256 and max200MiB. Install validates exact byte count/SHA; runtime read re-verifies bytes. Status reports verified install headers, not a fresh full hash. No fetch fallback exists. `HoleStemModel` is the pinned manifest convenience wrapper. Missing model fails `MODEL_MISSING` with zero output. Model storage is removable separately and may be evicted by browser storage policies.
