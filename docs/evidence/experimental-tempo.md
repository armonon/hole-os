# Experimental local tempo estimate

`audio.tempo` saves `hole.tempo-analysis/1` JSON from the selected immutable audio version. Load `tempo-analysis.js` before `actions.js`. Existing Flow authoring can select the action; an audio preview may call `HoleActions.preview/run('audio.tempo', {inputs:[{assetId,versionId}],projectId,parameters:{maxSeconds:60,budgetMs:10000}})`. The report is a document output, not WAV; it cannot feed another audio action. Original bytes remain untouched. Durable output provenance and report source pin the original version.

Implementation is original generic signal mathematics: per-channel squared energy in 10 ms windows, RMS positive differences, normalized autocorrelation over periods corresponding to 50–200 BPM. Channels contribute energy independently so opposite phase does not cancel. Near-equal periodicities select the shortest period for display, preserve competing candidates, and flag ambiguity. Scores are not calibrated confidence probabilities. Silence and less than eight seconds return null BPM. Key analysis remains unimplemented.

Bounds: browser-decodable source <=64 MiB, <=10 minutes/eight channels/50 million decoded samples (existing decoder checks after decode); analyze first 60 seconds by default, explicit8–120 seconds, <=12 million selected PCM samples, <=30 seconds configurable analysis budget (10 seconds default). Decoder allocation/time cannot be interrupted inside browser `decodeAudioData`; cancellation is checked after decoding and repeatedly during analysis, and before durable commit. Analysis yields every32 energy windows/eight lags. The analysis timer excludes decoding and storage. Partial source coverage is explicit. This is not a production music-analysis accuracy claim: soft attacks, subdivisions, syncopation, variable tempo, noise and meter remain limitations.
