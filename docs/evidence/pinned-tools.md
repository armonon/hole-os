# Exact-version previews and Quick Tools

The object preview and its Quick Tools now carry the exact displayed version into Carry, Download and Independent copy. Pinned placements and explicitly selected history versions no longer silently copy the current head. Independent copies record canonical parentVersionIds as well as source provenance; copying or carrying a trashed source is refused.

Object, media-tool and persistent-player routing use the selected immutable version MIME. If the head changes from text to image, the older text still previews as text. Open latest deliberately returns to the current preview instead of feeding non-text bytes to a text editor. Pinned native WebLab/experiment/tool sources are readonly bounded source previews with download/branch/latest choices; opening them does not silently recover a newer draft or execute its preview. Explicit latest-draft recovery leaves the pinned view first. Existing retained studio routes remain available. Independently reviewed readonly Moodboard and package-object renderers remain enabled for pinned previews; a blanket guard initially suppressed those renderers and was narrowed before release.

Observed regression: the pre-fix generated browser carried the newer head version from Quick Tools despite the old version being displayed. The corrected source browser journey verifies exact downloaded bytes, one pinned Carry reference, copied bytes and canonical lineage, historical text after an image head advance, current-format routing, and a pinned WebLab source that leaves its newer private draft unchanged. No page errors. The harness is scripts/verify-pinned-tools-browser.mjs; source override is explicitly labeled. Final generated-build verification passed with sourceOverride:false in Chrome156: the same byte/lineage checks plus readonly Moodboard rendering and refusal of a concurrently retargeted placement. Log: /tmp/hole-wave13-pinned-built.log. Independent review also exercised readonly package-object rendering.

This does not add immutable historical filenames to the Core schema; previews and downloads still use the asset's current display name. No browser/device-wide qualification is claimed.
