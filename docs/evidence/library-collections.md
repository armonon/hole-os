# Private native Librarian collections

This increment adds ordered, editable local reading collections without replacing the already qualified reader sessions. `src/library-collections.js` stores a collection as a canonical source asset with MIME `application/vnd.hole.reading-collection+json` and schema `hole.reading-collection/1`. Its entries contain exact local PDF/text version references and authored title, author, note, shelf and color metadata. Collection-level title, curator and description are authored locally. Membership removal never deletes source files.

## Retained contracts and scope

The owned retained Librarian source is `../tcc-operations/repos/librarian`, commit `53ffd4cf3781e7f11ee9f63a68b279e7c8dd0782`. Its `src/collections.js`, `src/pdf-storage.js` and `docs/collections.md` establish ordered local book metadata, source identity and separate hosted collection operations. The new module implements the local curation portion using Hole's existing exact-version reader. No original code, vendor bundle or license dependency was copied by this increment.

Retained local-draft JSON imports keep the complete bounded original object under `originalMetadata` and each original book record under `originalSource`, including unknown fields and source/license metadata. Native collection import also retains original source references, but clears all incoming local bindings. Even a matching foreign asset/version ID is unresolved until the user explicitly chooses a local version. No cross-origin IndexedDB access, remote URL fetch, catalog lookup, sign-in, public room, provider connection or publication occurs.

## Integration

Load `library-collections.js` after `library-model.js` and before `libraries.js`. The narrow Librarian-list mount calls `HoleLibraryCollections.mountList(ctx)`. The shared object renderer calls `openAsset(record,ctx)` before generic extension dispatch. It returns false for other MIME types. Root navigation, close and rendering preflights call `beforeLeave()` to freeze and flush without destroying the session. `cancelLeave()` restores its original control states if later navigation persistence fails; `dispose()` removes the guard only at actual unmount. These operations share the asynchronous mount lifecycle.

Pinned, explicit historical and non-head records are read-only. They do not load or recover the editable collection's draft. Reading an entry opens the existing Librarian reader with its exact source version, without modifying that reader's implementation. Advancing a source head never retargets the collection.

The model exposes `document`, `imported`, `resolve`, `createAsset` and `session`. `session` supplies `state`, `change`, `flush`, `recover`, `discard`, `save` and `beforeLeave`. Creation/import writes a durable request before a deterministic Core job; uncertain outcomes are exposed as resumable creation requests on the library list. Native saves likewise retain their attempt identity and use atomic Core output/job receipts. Mapped exact source versions are canonical parents on creation; edits retain the prior collection version plus all distinct mapped source versions, verified transactionally by Core. Unresolved foreign references do not become invented graph parents. Replaying an acknowledged save returns its existing immutable version rather than committing a duplicate.

Drafts are scoped to collection asset and original base version. Pending field values, including invalid color text, checkpoint after 150 ms. Reopening displays committed content until explicit Recover. Save validates metadata and exact source availability; a newer collection head refuses the save and retains the draft for export or explicit discard. Failed storage blocks navigation and unload while retaining in-memory fields. Flush drains newer edits arriving during a pending write. Lifecycle operations serialize asynchronous mount and disposal; closing during mount waits and disables detached handlers. An open source picker blocks leaving and invalidates late continuations on close. Pending input controls freeze during leave, restoring on failure rather than accepting text that cannot be saved. Active save and creation operations refuse navigation until settled.

## Bounds and limitations

Collections accept at most 50 entries and 1 MiB of native JSON. Original metadata and each original source record are bounded to 64 KiB. Text fields have fixed bounds. Local source selection is limited to active PDF/text versions up to the existing reader's 30 MiB limit; the picker explicitly lists up to 1,000 eligible versions. File imports do not include source bytes. A collection export is the committed private native document; a pending-draft export is separately labeled and includes recovery state.

This is not full retained Librarian catalog/hosted collection parity or native Bounce library/tag parity. Historical filenames remain Core asset display names, not an immutable filename model. There is no physical-device or screen-reader qualification claim.
