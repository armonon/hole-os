# Independent Day and Paperwork windows

Verified 28 October 2026 with actual Chromium 156.0.8078.48, generated local shell and disposable browser data. Run `node scripts/verify-tool-windows-browser.mjs` against port 5193.

Day and Paperwork each open independent runtime instances with separate window geometry and view roots over the same Core. Day task creation, dialog input retention when closing is refused, resize checkpoint, minimize/resume, navigation without remounting, explicit refresh and closing one instance while the other remains running pass. Reload retains the actual saved task. Arrangement restoration reopens a closed Day view with its saved geometry and retains the existing Paperwork instance; current content is read from Core. A 320px viewport keeps restored window bounds on screen.

Tool-owned dialogs must be finished or cancelled before checkpoint/close/minimize; a refused operation keeps input and the running instance intact. Refresh reads shared current data and also refuses while its dialog is open. Opening an asset uses the shared object surface. These windows do not claim independent document-editor sessions for every canonical app, automatic synchronization of every open view, or physical touch/assistive-technology qualification. Existing document-specific durable drafts and explicit recovery still apply. New-document draft keys and the global modal layer remain shared.
