# Private native Bounce libraries

The bounded local library adapter imports retained Bounce `library.json` into an immutable Hole source document, MIME `application/vnd.hole.bounce-library+json`, schema `hole.bounce-library/1`. It preserves original track metadata, folders, playlists, playback settings and unknown JSON fields. It neither scans original paths nor applies native gain/EQ/shuffle/repeat settings.

## Source and contracts

The owned retained checkout is `../tcc-operations/repos/bounce`, commit `1ce1a8432bafa9a656534dcbaf2323556d27ebd8`. `src/MusicLibrary.h` defines Track, Album, Playlist and PlaybackSettings. `src/MusicLibrary.cpp` save/load persists folders, tracks (`path`, title, artist, albumArtist, album, genre, track, disc, year, duration, dateAdded), playlists with ordered path slots, and playback settings. `src/TagReader.h` describes native C++/JUCE extraction; this increment does not port its tag readers or DSP. No upstream code or dependencies were copied, and no new license or open-source claim is made.

`src/bounce-library.js` retains the entire bounded imported JSON under `originalMetadata`, each source track under `originalSource`, and playlist unknown fields in the native playlist. Paths are inert: import requires explicit local exact-version mapping even when an incoming Hole reference happens to exist locally. Duplicate playlist slots retain their order and identity. Missing path references reject import rather than silently dropping members. Original metadata export preserves JSON values, not original file whitespace.

## Behavior and integration

Load after the existing library model and before `libraries.js`. `HoleBounceLibrary` exposes `MIME`, `schema`, `document`, `imported`, `resolve`, `createAsset`, `session`, `mountList`, `openAsset`, `beforeLeave`, `cancelLeave` and `dispose`. The only listening-list change mounts private libraries before the existing queue. Shared routing handles the native MIME and exact historical selection. Lifecycle uses prepare/flush, cancellation, and actual disposal; synchronous operation admission prevents navigation during import, mapping, reorder and save.

Songs, Albums and Artists views search imported/authored metadata. Album grouping uses albumArtist (artist fallback) plus album and sorts by disc/track. Metadata fields and playlist names are editable; playlist slots can move up or be removed. Removing membership never deletes audio. Mapping chooses an active exact local audio version. Individual Queue buttons use the existing listening model without starting playback. That shared queue deduplicates matching references; this is not whole-playlist queue replacement or duplicate-slot playback support.

A library save creates one immutable version with its prior version and mapped source versions as canonical parents. Source advances never retarget stored references. Historical/pinned views do not load newer editable drafts. Pending raw fields checkpoint locally, require explicit recovery after reopening and retain their original version base. A newer library head refuses save without overwriting either side. Revision-checked creation journals and save attempts reconcile exact Core job receipts after uncertain acknowledgement, avoiding duplicate assets/versions. Storage failure refuses leaving and warns on unload while pending work remains. Controls freeze during async operations; failed downstream navigation restores them. Filesystem paths and unsupported playback settings remain inert, including private original paths in explicitly exported metadata.

## Bounds and remaining parity

At most 50 tracks, 50 playlists and 500 playlist slots in total; native document at most 1 MiB; imported original JSON at most 256 KiB; each original track at most 64 KiB. Text and numeric fields have explicit bounds. Mapping lists at most 1,000 eligible local versions, each at most 100 MiB. Browser decoding remains format-dependent and the existing player reports failures. No external fetch, directory scan, OS library access, native tag rewriting, embedded artwork extraction, JUCE decoding/DSP, EQ, positive dB boost, shuffle or repeat-all is implemented. No physical-device or assistive-technology qualification is claimed. Original Bounce routes remain available.
