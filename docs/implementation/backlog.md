# Program ledger and release gates

Updated 26 October 2026 against the accepted [master brief](master-build-brief.txt), current source, tests, and evidence. Reviewed working tree: `codex/hole-os-overhaul`, based on `7d98b7251718b5615196bad2c793554f8573b6b1`. This is an implementation snapshot, not a claim that the complete program is shipped. The integrator records the final revision, settled build/test result, observed browser coverage and deployment destination in release evidence.

**Implemented / local checks** means the named operation exists with relevant automated or observed evidence. **Partial** means useful operations exist but accepted scope remains unfinished. **Open** means required implementation is absent. **Gated** identifies an actual engine, service, review or release dependency. Verification applies only to the demonstrated behavior/environment; delivery requires a verified release at a named destination. Missing production credentials do not block independent local implementation. No required package becomes optional because a narrower prototype works.

## Resume order

1. **Lead + Storage:** retain the passing browser backup/offline recovery baseline; finish the broader first-journey, integrated acceptance and release gates. Use disposable profiles; preserve real user data.
2. **Lead + Runtime + Actions:** close instance/playback/accessibility paths, registry/Carry/Time/Flow/Publish integration, sharing/conflict UI and real offline recovery. These remain independent work, not production-credential blockers.
3. **Studios + Actions:** connect actual mounted Luma editor through its authorized pipeline; then each retained native format/feature contract and missing media engine. Keep source/engine gaps explicit.
4. **Services + Build + Everyday:** finish Relay adapters/social contracts, Lab/package breadth, Browser Trails, Atlas/Tongue and everyday acceptance. Production hosting and Vault review are separate gates; continue available local work.

Day, Capture and Paperwork consolidate everyday use; Paper remains the document engine. Create/Forge, Actions/Flow and History/Time are shared capabilities. NOW and Circle remain distinct. Single-click opens; right-click/long-press shows tools. All presentations share identity. Implementation authorization does not make the product automatically send or publish on its users' behalf.

**Explicit future:** Care and remote native Windows/macOS/Linux application execution are not supplied by the browser runtime. Downloads cannot execute those apps; a future native/remote host needs authorization, isolation, lifecycle and qualification. Rich Universe furniture/interactive objects/physics remain the brief's explicit later capability packages. No other required row above is silently moved to “future.”
